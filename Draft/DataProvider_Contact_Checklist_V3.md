# 📊 외부 데이터 공급사 컨택 최종 체크리스트 (사장님 검토용)

**📋 목표:** 안정적이고, 정교하며, 비용 효율적인 금융 시계열 데이터 및 대체 Feature 확보
**💡 핵심 원칙:** 단일 소스 의존 금지. 여러 데이터를 통합 제공하는 Aggregator 형태의 벤더에 우선 집중합니다.

## 🥇 Part 1: 접촉 우선순위 벤더 리스트 (Top 3)

| 순위 | 데이터 유형 및 역할 | 기대 효과 | 비고 / 중점 검토 항목 |
| :--- | :--- | :--- | :--- |
| **1** | **Level-2 실시간 OHLCV Feed 제공사** | 가장 기본적인, 고신뢰도의 시계열 데이터 확보 (최우선) | 벤더 A급. 높은 빈도(Frequency)와 낮은 지연 시간(Latency)이 핵심입니다. |
| **2** | **글로벌 시장 심리 지수 API** | 거시 경제 및 시장 참여자들의 구조적 흐름 파악 (Feature 확장) | 변동성 예측에 필수적인 대체 데이터. 다양한 인덱스 제공 여부 확인. |
| **3** | **대체 데이터 소스 통합 플랫폼 (예: 뉴스 감성, 자본 흐름)** | 모델의 설명력(Explainability) 및 비선형적 패턴 포착 능력 강화 | 단순 데이터를 넘어 '관계성'을 파싱할 수 있는 구조를 가진 곳이 좋습니다. |

## ❓ Part 2: 벤더별 필수 문의 핵심 질문 (Must Ask Questions)

**[데이터 통합/정합성 관련]**
*   **시간 정렬 표준:** 모든 데이터는 UTC 기반으로 제공되며, 시간대 오차(Timezone mismatch)가 발생할 경우 어떤 방식으로 처리하는지? (필수: 밀리초 단위 지원 여부 확인)
*   **결측치 정책:** 데이터 공급이 중단되거나 누락되었을 때, 벤더 측에서 자체적으로 보간법(Interpolation) 또는 결측값 대체 가이드라인을 제공하는지? (FFill/Zero Fill 등 명시적 처리 방법 요청)

**[기술 및 비용 관련]**
*   **API Rate Limit:** 초당/분당 호출 제한(RPS/RPM)은 얼마이며, 이를 초과했을 때의 정책(Throttle/Quota Increase)은 무엇인지? (최소한 100+ RPS는 필요합니다.)
*   **데이터 히스토리 및 비용 구조:** 과거 데이터(Historical Data)를 어느 기간까지 제공하며, 이는 API 이용료와 별도인가요? 또한, 사용량에 따른 비용 체계가 명확해야 합니다.
